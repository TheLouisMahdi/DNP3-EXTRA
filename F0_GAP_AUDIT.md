## Executive findings

1. **CONFIRMED CODE GAP:** `PROFILE-055` / G120V8: its generated wire representation and selected RUK paths exist, but a complete Outstation runtime IEC/TS 62351-8 certificate acceptance, chain/signature, status/role/expiry and association/user binding path was not found in the inspected `RemoteUpdateKeys.cpp` and relevant handlers. IEEE Annex A.45.8 uses V8 only for asymmetric methods (68-71) and as an alternative to V10. An untrusted X.509/TLS certificate is not automatically a valid G120V8 user certificate. External certificate/authority profile remains an explicit blocker.
2. **CONFIRMED CODE GAP:** `SEC-T1-15`: `SSLContext::ApplyConfig` loads an optional CRL at context construction. There is no evidenced live 12-hour reevaluation, CRL hot reload, or established-connection revocation handling. IEEE 7.8.7.4.3 requires 12-hour default and one-hour resolution. CRL unavailability alone must not terminate an existing connection; a positively revoked active certificate must.
3. **SPECIFICATION CONFLICT:** `CFG-12`: Profile p4 selects static unsolicited on restart, while IEEE 4.6.6 Rule 2 restricts unsolicited responses to event data (with a narrow deprecated exception for G10V2/G40V2), and 5.1.1.1.1 requires a startup NULL unsolicited with **no objects** and no data before ENABLE_UNSOLICITED. `OContext::CheckForUnsolicitedNull` implements the NULL start. No general static-on-restart feature should be invented before a tracked owner disposition.
4. **SPECIFICATION CONFLICT:** `SEC-T1-13`: the addendum calls for a configurable 1-60 s change-cipher timeout; IEEE 7.8.5 links its configurable range to the 7.6.1.4.1 security reply timeout (maximum at least 120 s). The 2012 renegotiation model is not directly TLS 1.3 KeyUpdate. RFC 8446 forbids renegotiation; any KeyUpdate or reconnect adaptation requires explicit semantics, sender/receiver ownership, timeout and independent peer evidence.
5. **SOURCE ALREADY PRESENT, DO NOT REWRITE:** `LinkContext::ShouldConfirm` and bounded `NumRetries`; `TransportRx` fragment deadline; `CommandTask` non-retryable FC6; `EventBuffer`, `Database`, `MeasurementHandler`, `RemoteUpdateKeys` Methods 4/68 and numerous permanent tests. Audit exact selected subcases and actual Windows results before changing these paths.
6. **TRUTHFUL CAPABILITIES:** `DeviceAttributeSelection.cpp` deliberately excludes G0V209. Keep it omitted until all applicable SA v5 and G120V8 acceptance gates actually pass; do not claim full SA v5 due to a documentation-only change.

## Additional source findings verified at current GitHub HEAD

- **RUK association method invariant:** `RemoteUpdateKeys::MethodAllowed` allows both Methods 4 and 68 after `allowMethod68` is enabled, `RemoteUpdateKeys::Load` accepts each user's persisted method independently, and `Request` accepts a V10 method per user. IEEE 7.6.1.4.9 specifies one active Update Key Change Method between a given Master and Outstation. This is a concrete **static policy gap/risk** for mixed-method associations, not yet runtime-reproduced. Define the association-level selection, migration semantics and tests before patching.

- **CFG-09 already has product-layer filtering:** `cli/main.cpp::SimulatedCommands::SelectValue/OperateValue` checks Count=1 and CROB bytes 0x41/0x81 in `--rtu-io-profile`. Reuse this evidence and restrict the remaining work to owner-approved production policy, physical interlocks, authorization and tests.

- **CFG-10 already has product-layer selection:** `cli/main.cpp` sets `G2V2` absolute or `G2V3` relative variation on Outstation binary inputs. The library's `app/MeasurementInfo.cpp::BinaryInfo::DefaultEventVariation` is `G2V1` intentionally for generic use. Do not change the universal default; validate product configuration and wire behavior.

## Evidence boundaries, cross-cutting defects and non-defects

- P4-OPEN-01, RUK-OPEN-01 (SCS wrap), RUK-OPEN-02 (Method 68 DSA DER), P6-OPEN-01 (statistics threshold comparison), STAT-RETENTION (durability), G122-UNTIMED, and independently verified interoperability remain tracked. No official erratum is asserted.
- `PROFILE-001` remains unavailable by design; G0V209 should only be exposed after full selected SA v5 functional and wire evidence.
- `PROFILE-066` uses `SecurityStatEventPublisher::ReportAt` and falls back to untimed V1 when occurrence time is absent. Explicit V2 request behavior and quality transitions need tests and, if a genuine mismatch is found, a minimal fix.
- `SEC-T2-07` local RTU password and `SEC-T3-06` hashed human-credential storage cannot be certified from Windows Credential Manager records holding DNP Update Keys.
- `CFG-04` application retry bounds do not authorize generic retries of direct controls. IEEE startup NULL retransmissions are a separate state-machine rule.
- `CFG-07` the current default 5-second Master response timeout is not an IEEE-required value; do not promote a code default to product policy.
- `SEC-T1-09` MAC support is an interoperability choice constrained by negotiated supported algorithms and tag strength. The fact HMAC-SHA-256/16 is present in code does not establish that unchecked PDF options are selected.
- `SEC-T1-11` RFC 8446 specifies TLS 1.3 suite names and forbids legacy renegotiation; this is an external protocol compatibility reference, not a retroactive IEEE 2012 edit.
